# Live research contract v3

## Concrete defects addressed

The shared paper-team instruction requested liquidity assessment while the live prose validator forbade liquidity terminology. It also requested a stance/findings structure absent from the live schema. Live research now uses its own versioned, schema-aligned instructions. Execution uncertainty remains in the fixed UNKNOWN_NO_SPREAD_OR_DEPTH field. No prose or price validator was relaxed.

This conflict is observed in code; it is not a proven diagnosis of the preceding risk-manager rejection, whose rejected text was not retained.

## Structured objection accounting

Each specialist concern receives a stable role/index ID. Debate and conclusion must acknowledge every supplied concern and mandatory missing-data key exactly once. Missing, duplicate, invented or replaced IDs stop the run and retain rejection diagnostics. All original concerns remain in the report; an acknowledgement never resolves an objection or grants trade authorization.

This verifies coverage, not meaningful engagement with objections. Human review is still required to assess whether the narrative accurately describes evidence and disagreements.

## Risk context

Every request receives the EUR 20 maximum planned loss, 22:00 Europe/Dublin entry cutoff, no-overnight policy, local evaluation timestamp, cutoff status, unverified broker eligibility and absent trade plan. This is research context only, not a substitute for deterministic trade-plan enforcement. Research may run after the entry cutoff, but trade_authorized remains false.
